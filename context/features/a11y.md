# Accessibility

**What / where:** Cross-cutting a11y, not one screen. Screen-reader labels, non-color status cues,
touch-target sizing, and color contrast across the app. Label strings live in `src/i18n/strings.ts`
under the `// Accessibility` block (`a11y*` keys) — always via `useStrings()`, never hardcoded.

## Gotchas / lessons

- **Icon-only `Pressable` needs both** `accessibilityRole="button"` + `accessibilityLabel`. A
  `Pressable` whose child is a `Text` is already read by SR from that text — don't double-label it.
- **`@/tw` `Pressable` forwards a11y props** straight to RN `Pressable`. Works as expected.
- **Tab-bar buttons get a11y for free** — React Navigation injects `accessibilityRole`/label into
  the `tabBarButton` props; the custom button in `(tabs)/_layout.tsx` spreads them, so don't add
  labels there.
- **Color-alone status (WCAG 1.4.1):** calendar over-days `underline` the count (in addition to the
  red token) so "over limit" isn't conveyed by hue alone; the per-cell SR label also says it in words.
- **Touch targets:** prefer `hitSlop` over growing the box when ≥44pt would change the visual — e.g.
  progress range chips (`py-2`) get vertical `hitSlop`; 32×32 calendar arrows already had `hitSlop={8}`.
- **Contrast:** dark-theme `textDim` passes AA; **light-theme `textDim` `#6C7B6D` ~4.1:1 fails AA 4.5**
  for small text — open residual in `roadmap.md [a11y]`. Compute against `bg`/`card` per theme, not
  one fixed background.
